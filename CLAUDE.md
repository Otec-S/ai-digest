Контекст для будущих сессий Claude Code в этом репозитории — то, что не выводится из самого кода.

## Статус проекта

Реализованы этапы 1–6 из исходного ТЗ (сбор → дедуп → ранжирование → агент → рендер → деплой).
Шаг поиска реализован через `src/collect/search.ts` (`SearchProvider`/`TavilyProvider`, Tavily
Search API) — выбрана вместо Brave, у которого нет бесплатного плана. `TAVILY_API_KEY` в `env.ts`
опционален: если не задан, а в теме есть `search_queries`, шаг поиска пропускается с предупреждением
в логе (RSS-фиды при этом собираются как обычно).

## Известные грабли (наступили в процессе разработки)

- **У Anthropic нет официального RSS.** `anthropic.com/news/rss.xml` — 404. В `config/topics.yaml`
  вместо него используется `https://news.google.com/rss/search?q=site:anthropic.com&...` — рабочий,
  но это Google News, а не первоисточник. Проверяйте curl'ом перед тем, как менять фиды.
- **jsdom катастрофически медленно парсит `<script>`/`<style>` реальных страниц** (минифицированный
  CSS/JS современных сайтов) — прогон вставал на десятки минут. В `collect/fetchArticle.ts` эти теги
  вырезаются regex'ом до создания `JSDOM`, и `VirtualConsole` глушит его шум об ошибках парсинга CSS.
  Не убирайте это без крайней необходимости.
- **`AbortController` в `fetchArticle.ts` покрывает только сетевой `fetch`, не сам парсинг DOM** —
  синхронный CPU-bound код нельзя прервать через сигнал. Таймаут — это защита от сети, а не от
  тяжёлого HTML.
- **CLI обязан звать `process.exit()` явно** после `run()` — иначе процесс зависает из-за открытых
  keep-alive сокетов `fetch` и не завершается сам (это ломает systemd `Type=oneshot`).
- **MarkdownV2-экранирование — реальный источник багов.** Одна точка в неэкранированной дате в шапке
  Telegram-сообщения (`formatDigestMessages`) уронила боевую отправку с `400 Bad Request`. Тесты
  ловят это плохо, если проверяют `toContain` без явного `not.toContain` на неэкранированный вариант —
  см. `render/telegram.test.ts`.
- **zod v3 не умеет сама генерировать JSON Schema.** `agent/schema.ts` держит `digestResultJsonSchema`
  руками синхронно с `DigestResult` — при правке одного не забудьте другое.

## Деплой (сервер общий, не выделенный)

Прод — `sg-files-prod` (78.47.166.130), на нём же nginx, Docker, `tg-monitor` и другое. Из-за этого:

- **Не менять системную таймзону** (`timedatectl`) — сервер в `Europe/Moscow`, другие сервисы на неё
  рассчитывают. `OnCalendar=` в `deploy/ai-digest@.timer` пересчитан вручную под неё (05:00 MSK =
  07:00 Asia/Tashkent), а не наоборот через смену tz.
- `ProtectSystem=strict` + `ReadWritePaths=/opt/ai-digest/data ...` требует, чтобы эти директории
  существовали ДО старта юнита, иначе systemd падает с `226/NAMESPACE`. Поэтому в
  `deploy/ai-digest@.service` есть `ExecStartPre=/bin/mkdir -p ...` — не убирайте.
- На свежем сервере `better-sqlite3` собирается из исходников (нет прекомпилированных бинарников под
  свежие версии Node) — нужен `build-essential` (`make`, `g++`), иначе `npm ci` падает на node-gyp.
- Код на сервер доставлялся через `git archive | scp`, не `git clone` — репозиторий на GitHub
  приватный, а класть токен доступа в удалённую shell-историю не хотелось. Если понадобится `git pull`
  на сервере, там потребуется отдельно настроить deploy key.

## Валидация окружения

`ANTHROPIC_API_KEY` обязателен всегда (агент вызывается и в `--dry-run`). `TELEGRAM_BOT_TOKEN`/
`TELEGRAM_CHAT_ID` обязательны только для реальной отправки — `requireTelegramConfig()` в `env.ts`
проверяет это отдельно, после dry-run-ветки в `index.ts`. Не делайте их обязательными в общей схеме.
